# v1 specification

The decisions of the design discussion on 2026-10-22. The terms are in
[`GLOSSARY.md`](../GLOSSARY.md), the product context is in [`PRODUCT.md`](../PRODUCT.md), and the
architecture decisions are in [`docs/adr/`](./adr).

## Scope

- **v1:** the habit list, the page of a habit, create and edit a habit, delete a habit (with an
  undo toast), manual order of the habits (drag), and an installable PWA (added on 2026-10-31, at
  the owner's request; see "Installable app").
- **v2:** archive, import and export, and an undo history with Cmd+Z.
- **Later, or never:** streaks, statistics, reminders and widgets.

## Habits

- A Habit has an icon (an emoji, or the name of a Phosphor icon), a name, a description, a color
  from a fixed palette, a Direction (`build` or `quit`) and a Kind.
- The Kind cannot change after the person creates the Habit. All other fields can change.
- The Direction changes only the words (for example, a quit Habit calls its Target "Limit"). A quit
  Habit looks the same as a build Habit.

| Kind     | Fields                                                    | Intensity of a Day                                                    |
| -------- | --------------------------------------------------------- | --------------------------------------------------------------------- |
| `check`  | none                                                      | full when the Entry exists                                            |
| `number` | optional unit, optional Target, Step (default 1)          | value / Target, maximum 100%; without a Target, full for a value > 0 |
| `choice` | 1 to 12 Options, no order                                 | full; the emoji (or the first letter) of the Option shows where space permits |
| `scale`  | 2 to 5 Options, in order                                  | the position of the Option: the first is the lightest, the last is full |
| `text`   | none                                                      | full when the text is not empty                                       |

- A number value can have decimals. A change of the Target applies to all past Days.
- An Option has a label, an optional emoji and a stable ID. A new label does not change old
  Entries. An Option that Entries use is retired, not deleted: the input does not offer it, but
  old Entries show it. A new order of a scale changes the Intensity of past Days.

## Days and Entries

- A Day is a local calendar date (`2026-10-22`), without a time or a time zone.
- A Habit has a maximum of one Entry for each Day. A Day without an Entry has no data.
- The person can change any past Day, also a Day before the Habit existed. Future Days are locked.

## Screens

- **Habit list.** Each row: the icon and the name at the left (a long name is cut), and the last
  Days as squares at the right: 5 Days on a narrow (phone) screen, 7 on a wide screen. Today is
  the square at the right. One header row above the list shows the weekday letter and the date of
  each column. No cards. A tap on the row (not on a square) opens the page of the habit.
- **Habit page.** The icon and the name, then a grid of the last 12 months (like GitHub), then a
  calendar. The grid scrolls sideways and opens at today. It takes no input, but a tap on a month
  in the grid moves the calendar to that month. The calendar shows one month, with the date in a
  notch at the corner of each square. A swipe (also on a trackpad) moves between months: the
  current month first, past months with a swipe to the right, no future months. Under the days,
  near the thumb: the name of the month, which opens a picker of the month and the year, and the
  arrows. Back and Edit float at the bottom of the screen.
- **Create and edit.** On a phone: a bottom sheet that changes its height between the steps (in
  the manner of Family). On a desktop: a centered dialog with the same height change. The edit
  form contains the delete button.
- **Input of a value** (number, choice, scale, text): on a phone, a small bottom sheet. On a
  desktop, a popover at the square.
- On a phone, each sheet has a URL, so the back gesture closes it.
- On a desktop, the layout is the phone layout in a 600px column, with a base font of 20px. The
  page of a habit opens beside the list, not in its place, and the list makes room for it as the
  window narrows: first it drops the Days, then the names, and keeps the icons. Below 640px the
  page takes the place of the list, as on a phone.

## Input

- No save buttons: each change applies immediately.
- `check`: a tap toggles the Day. A press and drag paints the Days: the first square sets the state
  (set or clear), and each square under the finger gets the same state. In the calendar, painting
  starts after a hold of approximately 200 ms, so a fast swipe still moves between months.
- `number`: a tap adds the Step, also above the Target. A long press opens the input: the exact
  value, −Step, +Step, "= Target" and "Clear".
- `choice`, `scale`, `text`: a tap opens the input.
- Haptics where the browser supports them.
- Order of habits: a long press on the icon or the name lifts the row, then a drag moves it.
- Delete a habit: no confirmation. The habit goes away, and a toast offers Undo.
- After a paint and after a delete, a toast offers Undo.

## Data

- **Packages** ([ADR 0001](./adr/0001-convex-behind-the-data-package.md)): `@habit/core` (domain
  types and rules, plain TypeScript), `@habit/data` (the Convex functions and the React hooks; the
  only package that imports Convex), `apps/web` (the screens).
- **Store:** the client cache of Convex. One live subscription gets the Habits and the Entries of
  the last 13 months. Older months load when the calendar goes to them. (A Convex query can read a
  maximum of 32,000 documents.) Optimistic updates use `withOptimisticUpdate`. UI state stays in
  React state and in the URL.
- **Writes** ([ADR 0002](./adr/0002-offline-ready-writes.md)): client UUIDv7 IDs, `setEntry` and
  `clearEntry` (no toggle), `updatedAt` with last write wins, soft delete.
- **Undo:** each user action records its inverse. The undo toasts of v1 use it, and the Cmd+Z
  history of v2 will use it.
- **Instant start:** the app keeps the last snapshot of the data in IndexedDB, with the time of
  save, the user ID and the schema version. At start, the app shows the snapshot only when the
  user and the schema version are the same and the snapshot is less than 24 hours old. Otherwise
  the app keeps its loading screen until the live data comes, and shows the list complete. A tap before the live data comes waits in a
  queue and applies when the live data comes.
- **Offline:** the app opens without the network and shows the snapshot (see "Installable app").
  Writes without the network are not in v1.

## Installable app

- A web app manifest (name "Habit", standalone, start URL `/`) and the iOS tags: the person adds
  the app to the Home Screen from Safari, and it opens without the browser's bars.
- A service worker caches the app shell (the HTML, the scripts, the styles, the main fonts and the
  icons). The app opens at once, also offline, and then shows the snapshot as on every start. The
  worker never answers a request to Convex or Clerk.
- A new deploy reaches an open app without a manual cache clear: the worker updates itself, and
  the page loads the new version at its start or the next time it comes back to the screen.
- Details, the caching rules and the checks on an iPhone: `docs/notes/pwa.md`.

## Sign-in and access

- Clerk, with Google first. In the installed app the sign-in screen also offers an email code:
  on iOS, Google's page opens in a Safari sheet that does not share its cookies with the installed
  app, so a Google sign-in there does not reach the app (`docs/notes/pwa.md`).
- Only the owner gets data. `authQuery` and `authMutation` (made with the custom functions of
  `convex-helpers`) compare the user ID from Clerk with the owner ID in a Convex environment
  variable. Another user sees a "no access" screen.

## Hosting

Convex Cloud and Vercel (a static SPA). For now the app runs at habit.tem.sh on the dev backends
(`docs/deploy.md`).
